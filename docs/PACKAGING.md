# OPNsense package integration status

This repository currently provides a direct source installer and in-place upgrade script. It does **not** yet claim to produce a signed, repository-ready OPNsense `.pkg`.

The included `Makefile` is a starting point for the OPNsense plugin build framework. Its maintainer field (`maintainers@example.invalid`) is deliberately a placeholder and must be replaced before package publication.

## Work required before official package submission

1. Select the intended OPNsense plugin branch/release (currently targeted at 26.7.x).
2. Review the current [OPNsense plugins repository contribution/build instructions](https://github.com/opnsense/plugins/blob/master/README.md).
3. Place the plugin under the appropriate category directory in a fork/working tree of `opnsense/plugins`, following the exact layout and package manifest conventions for that branch.
4. Replace placeholder maintainer metadata with an approved project maintainer contact.
5. Verify all installed files and directories are represented in the package manifest/plist generated by the framework.
6. Run the framework's lint, package, install, upgrade, and remove targets in the matching OPNsense build environment.
7. Test package install/upgrade/deinstall against a disposable firewall, verifying that user feed data and custom Unbound/Cron configuration are handled as documented.
8. Build and test the package for every OPNsense release/architecture you intend to support.

Do not publish a `.pkg` or describe this repository as an official OPNsense package until those steps are complete. The official plugins repository explains that plugin Makefiles use the repository build framework and describes targets such as `lint`, `package`, `upgrade`, and `remove`.
