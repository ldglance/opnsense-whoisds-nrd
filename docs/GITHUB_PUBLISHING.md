# Publishing this project on GitHub

This guide describes how to publish the repository source. It does not publish an OPNsense `.pkg` or configure a package repository.

## Repository settings

Recommended repository name: `opnsense-whoisds-nrd`.

Recommended initial settings:

- Visibility: Public, if the intent is community sharing.
- Default branch: `main`.
- Add the description: `Community OPNsense integration for the WhoisDS Newly Registered Domains feed and Unbound DNSBL.`
- Add topics: `opnsense`, `freebsd`, `unbound`, `dnsbl`, `newly-registered-domains`, `security`, `python`.
- Do not add an autogenerated README, license, or `.gitignore` when creating the repository; those are already included here.
- Keep Actions enabled so the source-validation workflow can run.

## First push from the repository folder

After creating an empty GitHub repository, extract this source bundle and run these commands from the folder containing `README.md`:

```sh
git init -b main
git add .
git status --short
git diff --cached --stat
git commit -m "Initial public release of OPNsense WhoisDS NRD"
git remote add origin https://github.com/OWNER/opnsense-whoisds-nrd.git
git push -u origin main
```

Replace `OWNER` with the GitHub account or organization that will maintain the project. Review `git status` and the staged diff before committing. Do not add live firewall exports, domain archives, screenshots containing private information, or runtime state files.

## After the initial push

1. Wait for **Actions → Source validation** to complete.
2. Review repository **Settings → General → Pull Requests** and enable the protections appropriate for the project.
3. Consider enabling private vulnerability reporting before inviting users to report issues.
4. Create a versioned release only after the release has passed the OPNsense appliance checklist in `docs/TESTING.md`.
5. Do not label a source ZIP as an installable OPNsense package; package integration remains a separate task documented in `docs/PACKAGING.md`.
